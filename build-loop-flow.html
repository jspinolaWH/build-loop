Scan the entire codebase and generate architecture context

③ Requirement graph analysis NEW — runs once, before queue starts
/bl-graph-analysis — reads all requirements together before building any of them
This is the step that makes the loop intelligent. Before a single line of code is written, the agent understands the full picture.
1. Existing Code Coverage
scans codebase per requirement
For each requirement, scans the existing codebase to find partial implementations.

Tags each requirement as:
FRESH — nothing exists yet
PARTIAL — something exists, build on top
COVERED — may already be done

Prevents the build agent from creating a duplicate service or component when one already exists at 80%.
2. Dependency Mapping
reads prd.json relationships
Maps which requirements depend on others.

Example: REQ-004 needs the data model from REQ-001. If REQ-004 is built first, it will invent the model and conflict later.

Produces a dependency graph so the queue is sorted in the right build order — foundations first, features on top.
3. App Location Mapping
maps to routes + pages
For each requirement, identifies where in the app it lives:

— Which route/URL it appears at
— Which page or component renders it
— What user role accesses it
— What action triggers it

Stored in the graph so the final summary can say exactly where to manually test each feature.
Output: build-loop/req-graph.json — dependency order, coverage tags, app locations, existing file pointers per requirement.
The orchestrator re-sorts the queue using this graph. The design and build agents read it so they know what came before, what comes after, and what already exists.

Auto-loaded · from spec-shaping
domain-nexus.md, domain-ledger.md etc. Business rules, entity definitions. Loaded based on squad routing in prd.json.

⑦ State files — everything on disk, resume at any point
prd.json
Source of truth for all requirements. Updated after every phase — passes, needs_review, iteration count, notes.
req-graph.json ★ new
Dependency order, coverage tags (FRESH/PARTIAL/COVERED), app locations, existing file pointers. Used by design and orchestrator.
state.json
Active requirement, current phase, iteration count. Loop resumes exactly here if interrupted.
context/
be-architecture.md + fe-architecture.md from bootstrap. Shared across all requirements.
plans/{id}.md
Implementation plan from /bl-design. One per requirement. Input to /bl-build.
gaps/{id}.md
Gap report per requirement. Which criteria pass/fail, what to fix. Input to next /bl-build iteration.
