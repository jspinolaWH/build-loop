PHASE B — RUNS ONCE
Graph analysis
Reads all requirements together. Maps dependencies between them. Tags each as FRESH / PARTIAL / COVERED based on existing code. Identifies where each feature lives in the app. Produces a dependency-sorted build queue — foundations are always built before the features that depend on them.

PHASE C — REPEATS FOR EVERY REQUIREMENT IN THE SORTED QUEUE
PRE-FLIGHT
Spec quality check
Checks 3 rules before any work starts: Silence (does it have acceptance criteria?), Ambiguity (are criteria measurable?), Wishful thinking (are criteria actually testable?). If any fail → flag the requirement, skip it, move to the next. No iterations wasted on a bad spec.
↓
PHASE 1 — /BL-DESIGN
Design
Reads the graph entry for this requirement: coverage tag, dependencies already built, where in the app it lives. Loads domain knowledge (business rules) and Oliver's UX patterns. Writes a full implementation plan — which files to create or edit, BE logic, FE components, routing. Design runs once per requirement only. Retries go straight to Build.
↓
PHASE 2 — /BL-BUILD
Build
Implements the plan (or fixes gaps on retry). Backend first, then frontend. Runs the build to check for compile errors and auto-fixes up to 3 rounds.
Oliver's brand hook fires here — every time a .jsx or .css file is edited, brand-check.sh loads the WasteHero brand skill. Claude can only use design tokens from Oliver's Figma system. This happens automatically, not by the orchestrator.
↓
PHASE 3 — /BL-GAP-CHECK
Verify
First checks the build compiles. Then scans the code against every acceptance criterion — reads the actual files, doesn't just grep. Returns PASSES or GAPS_FOUND. Updates prd.json. Writes a gap report with exactly what's missing and which files to fix.
✅ PASSES
All criteria implemented. Build compiles. Marked passes: true. Manual test path written to summary. Next requirement begins.
🔁 GAPS FOUND
Gap report fed back into Build. Iteration counter increments. Loops back to Build — skips Design. Repeats until passes or max iterations hit.
⚠️ MAX ITERATIONS REACHED
Marked needs_review: true with notes. Last gap report preserved. Loop does not stop — next requirement begins immediately.

③ Requirement graph analysis NEW — runs once, before queue starts
/bl-graph-analysis — reads all requirements together before building any of them
Before a single line of code is written, the agent understands the full picture.
1. Existing Code Coverage
scans codebase per requirement
Tags each requirement:
FRESH — nothing exists yet
PARTIAL — something exists, build on top
COVERED — may already be done

Prevents creating a duplicate service or component when one already exists at 80%.
2. Dependency Mapping
reads prd.json relationships
Maps which requirements depend on others.

Example: REQ-004 needs the data model from REQ-001. If built first, it invents the model and conflicts later.

Produces a dependency graph — sorted so foundations are built first.
3. App Location Mapping
maps to routes + pages
For each requirement:
— Which route/URL it appears at
— Which page renders it
— What user role accesses it
— What action triggers it

Used in the final summary so you know exactly where to manually test.
Output: build-loop/req-graph.json (machine-readable, used by orchestrator + agents) and build-loop/req-graph.md (human-readable summary with dependency tree).
The orchestrator re-sorts the queue using sorted_order from the json. Design and build agents read the json to know what came before, what comes after, and what already exists.

⑦ State files — everything on disk, resume at any point
prd.json
Source of truth. Updated by gap-check after every verify — passes, needs_review, iteration count, notes.
req-graph.json
Machine-readable graph. sorted_order used by orchestrator. Dependency + coverage + location data used by design + build agents.
req-graph.md
Human-readable summary of the graph. Build order list, dependency tree, coverage breakdown, warnings (circular deps etc.).
state.json
Active requirement, current phase, iteration count. Loop resumes exactly here if interrupted.
plans/{id}.md
Implementation plan from /bl-design. One per requirement. Input to /bl-build on first run.
gaps/{id}.md
Gap report per requirement. Final line is PASSES or GAPS_FOUND. Input to /bl-build on retry iterations.
