PHASE C — REPEATS FOR EVERY REQUIREMENT IN THE SORTED QUEUE
PRE-FLIGHT
Spec quality check
Checks 3 rules before any work starts: Silence (does it have acceptance criteria?), Ambiguity (are criteria measurable?), Wishful thinking (are criteria actually testable?). If any fail → flag the requirement, skip it, move to the next.
↓
STEP 1 — /BL-DESIGN
Design
Reads graph entry, domain skills, architecture context, Figma design specs, and UX patterns. Writes a full implementation plan — which files to create or edit, BE logic, FE components, routing. Runs once per requirement. Retries skip this and go straight to Build.
↓
STEP 2 — /BL-BUILD
Build
Implements the plan (first run) or fixes gaps and FE test failures (retries). Backend first, then frontend. Runs build check and auto-fixes compile errors up to 3 rounds. Snapshots every file touched before editing so /bl-reset can undo it.
Brand hook fires here — every time a .jsx or .css file is edited, brand-check.sh loads the WasteHero brand skill. Claude can only use design tokens from the design system. Card guards also enforce when to use LayoutWithFilters vs a card.
↓
STEP 2.5 — /BL-FE-TEST · NEW
FE Runtime Test
Starts the FE and BE dev servers if not already running. Runs Playwright headless — logs in as your user, navigates to the requirement's route, and intercepts every GraphQL call to /graph-api/. Parses the response body and fails if any operation returns an errors array. That's the GraphQL equivalent of a 500/400 — the HTTP status is always 200. Takes screenshots at every stage.
Why not HTTP status codes? The FE talks to Django via GraphQL. GraphQL always returns HTTP 200 — errors are in the response body: {"errors": [{"message": "..."}]}. This test catches resolver failures, permission errors, and null data that static code scans miss entirely.
↓
STEP 3 — /BL-GAP-CHECK
Verify
Checks build compiles. Reads the FE test report — any failed GraphQL operations become explicit gaps (pointing at the resolver that needs fixing). Then scans code against every acceptance criterion. Writes a gap report combining static + runtime findings. Returns PASSES or GAPS_FOUND.
✅ PASSES
Build compiles. FE test found no GraphQL errors. All criteria implemented. Marked passes: true. Screenshots + manual test path written to summary.
🌐 FE TEST FAILS
A GraphQL operation returned errors. The failing operation + error message fed into the next Build iteration. Loops back to Build — skips Design.
🔁 GAPS FOUND
Static gap report + any FE test failures fed back into Build. Iteration counter increments. Loops until passes or max iterations hit.
⚠️ MAX ITERATIONS REACHED
Marked needs_review: true. Last gap report + FE test report + screenshots preserved. Loop does not stop — next requirement begins immediately.
▼
all requirements processed

③ Requirement graph analysis — runs once, before queue starts
/bl-graph-analysis — reads all requirements together before building any of them
Before a single line of code is written, the agent understands the full picture.
1. Existing Code Coverage
scans codebase per requirement
Tags each requirement:
FRESH — nothing exists yet
PARTIAL — something exists, build on top
COVERED — may already be done

Prevents creating a duplicate service or component when one already exists at 80%.
2. Dependency Mapping
reads prd.json relationships
Maps which requirements depend on others.

Example: REQ-004 needs the data model from REQ-001. If built first, it invents the model and conflicts later.

Produces a dependency graph — sorted so foundations are built first.
3. App Location Mapping
maps to routes + pages
For each requirement:
— Which route/URL it appears at
— Which page renders it
— What user role accesses it
— What action triggers it

Used by bl-fe-test to know which route to navigate to during Playwright tests.
Output: build-loop/req-graph.json (machine-readable) and build-loop/req-graph.md (human-readable).
The orchestrator re-sorts the queue using sorted_order. Design, build, and FE test agents read the json to know what came before, what already exists, and where in the app to navigate.

⑦ State files — everything on disk, resume at any point
prd.json
Source of truth. Updated by gap-check after every verify — passes, needs_review, iteration count, notes.
req-graph.json
Machine-readable graph. sorted_order used by orchestrator. Dependency + coverage + location data used by design, build, and FE test agents.
req-graph.md
Human-readable summary of the graph. Build order list, dependency tree, coverage breakdown, warnings (circular deps etc.).
state.json
Active requirement, current phase (now includes "fe-test"), iteration count. Loop resumes exactly here if interrupted.
plans/{id}.md
Implementation plan from /bl-design. One per requirement. Input to /bl-build on first run.
gaps/{id}.md
Gap report. Now includes FE test verdict header and failed GraphQL operations as explicit gap entries. Final line: PASSES or GAPS_FOUND.
fe-tests/{id}.md
FE test report per requirement. Lists every GraphQL operation intercepted, which ones had errors, the error messages, and suggested fix. Final line: PASSES or FAILS.
screenshots/{id}-*.png
Playwright screenshots: after-login, page-load, final state. Preserved even when the test fails — so you can see exactly what the app looked like when it broke.
config.json
Local credentials for FE tests. Gitignored. Fields: test_user (username + password), fe_port (3000), be_port (8000), be_graphql_path (/graph-api/). Copy from config.json.example.
logs/fe-server.log
Vite dev server stdout if bl-fe-test started it. Also be-server.log for Django. Inspect here if FE_TEST_RESULT: ERROR servers_not_ready.
snapshots/{id}/
File snapshots taken before bl-build edits. Used by /bl-reset to restore original state. manifest.json lists every file touched.
